# Angular Latest Rules (v20+)

## Component Architecture
- **Standalone by Default**: Always use standalone components.
- **No Standalone Flag**: Do NOT set `standalone: true` in decorators; it is the default in v20+.
- **Change Detection**: Always set `changeDetection: ChangeDetectionStrategy.OnPush`.
- **Host Bindings**: Do NOT use `@HostBinding` or `@HostListener`. Use the `host` property in the `@Component` decorator.
- **Bindings**: Do NOT use `ngClass` or `ngStyle`. Use native `class` and `style` bindings (e.g., `[class.active]="isActive"`).

## Signals & State
- **Signal State**: Use `signal()` for all local component state.
- **Derived State**: Use `computed()` for all derived state.
- **Inputs/Outputs**: Use `input()`, `output()`, and `model()` functions instead of `@Input` and `@Output` decorators.
- **Update Logic**: Do NOT use `mutate` on signals; use `update` or `set`.

## Dependency Injection
- **Inject Function**: Use the `inject()` function for dependency injection instead of constructor injection.
- **Root Services**: Use `providedIn: 'root'` for singleton services.

## Templates & Control Flow
- **Native Control Flow**: Use `@if`, `@for`, and `@switch`. NEVER use `*ngIf`, `*ngFor`, or `*ngSwitch`.
- **Template Logic**: Keep templates simple. Do NOT use arrow functions or globals (like `new Date()`) directly in templates.
- **Async Pipe**: Use the `async` pipe to handle Observables.

## Performance & Side Effects
- **@for Tracking**: You MUST include the `track` expression when using `@for` to prevent performance issues (e.g., `@for (item of items(); track item.id)`).
- **Effects**: Use `effect()` ONLY for side effects (e.g., DOM manipulation, logging). Do NOT use `effect()` to update other signals, as this can cause infinite loops and unpredictable state.
- **Deferrable Views**: Use `@defer` to lazy-load heavy or non-critical components in the template to improve initial load time.
